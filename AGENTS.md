- Use the existing shared Application page for both self-service and staff registration, because both require identical personal, academic, preference, and document fields.
- Route staff uploads for a newly created student through the authenticated manage-users function, because storage ownership policies prevent staff from writing directly into another user's folder.
- Treat submitted receipts as pending until an admin reviews the image and explicitly verifies or rejects the payment; notify admins in the dashboard through polling while it is open.
- Apply the configurable Grade 12 cutoff in a database trigger; only waiting-listed or rejected students are blocked from exam and payment progression.
- Store news articles with admin-only writes and public published reads; keep news photos private with published-article access, because unpublished content must remain hidden.
- Resolve uploaded hero photo pointers against the project's preview asset host so they display on both Lovable and external hosts, where relative asset paths otherwise fall through to the SPA HTML page.
- Amharic translation is done at runtime by src/lib/i18n.tsx (DOM text walker + AI translate edge function, cached in localStorage), because hand-maintained dictionaries can't cover every page; mark untranslatable content with data-no-translate.
- Department head scoring/placement lives in department_placements and is written only via the evaluate_application security-definer RPC, so heads can't edit applications directly and referrals move the student to their next choice atomically.
- Existing-student manual-form attachments use authenticated manage-users actions for admins/sub-admins, preserving all stored files because staff cannot upload directly into another student's folder.
- Department-choice changes use a service-only atomic RPC with actor role and individual staff_permissions checks; they reset entry evaluation to the first choice so placement remains consistent. Keep the manage-users department catalog aligned with src/data/departments.ts.
- Share student-record validation in manage-users/record-rules.ts and run its Bun tests when permissions or manual-form rules change.
- Native department exams use server-validated RPCs and immutable attempt question snapshots/deadlines; students cannot write grades or reset attempts, so browser controls are deterrents rather than authority.
- Admin creation authority is backfilled only for existing admins and never delegated to created admins; enforce it in manage-users and a user_roles trigger to prevent direct privilege escalation.
- Shared application birth-date controls use Ethiopian calendar conversion while retaining Gregorian ISO storage, so existing records, age calculations and photo autofill remain compatible.
- Student Excel exports use the shared filter predicate for dates, department, program, status and search, so preview counts match downloaded records.
- Grade 12 total and subject extraction share the verify-grade subject catalog and normalization with the Application page, so student and staff autofill use identical keys and reject unreadable scores.
